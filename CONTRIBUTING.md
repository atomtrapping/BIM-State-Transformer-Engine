# Contributing to GAT

GAT treats numerical state, evidence, verification, and provenance as one
assurance boundary. Changes should be small enough to review and should add
executable evidence for their claims.

## Change process

1. Work on a topic branch. Do not push implementation commits directly to
   `main`.
2. Open a pull request and wait for all required CI jobs to pass.
3. Keep each pull request focused on one falsifiable milestone.
4. For large or security-relevant changes, include an adversarial review pass
   before merge and resolve or explicitly document every finding.
5. Describe limitations and negative results alongside successful behavior.

## Branch protection (repository setting — apply this)

Branch protection is a GitHub setting and cannot be enforced by this file.
It is the single most load-bearing item in this document: `main` was once
merged with red CI and spent two days with nineteen of `GatSession`'s twenty
public methods deleted, because nothing required the checks to pass.

At **Settings → Branches → Add branch ruleset**, targeting `main`:

- Require a pull request before merging.
- Require status checks to pass, and mark these required:
  - `test (3.11)` and `test (3.12)` — suite, demos, and record drift
  - `test-extras` — the full suite with the optional stack and zero skips
  - `test-public-ifc` — public models and the corpus-dependent records
- Require branches to be up to date before merging.
- Block force pushes.

`test-openusd` and `test-sp1-beam` are slower and may stay advisory; the
four above are the ones that catch a broken public surface.

## Validation records

Everything in `validation/` is generated by `validation/records.py` and
asserted by `tests/test_validation_records.py`. Do not edit a record by
hand — regenerate it:

```console
python validation/regenerate.py                  # shipped models
python validation/regenerate.py --corpus DIR     # and the public corpus
python validation/regenerate.py --check          # what CI runs
```

A changed digest in that diff means a changed decision. Read it before you
commit it; that is the whole point of the directory. Records that are not
reproducible do not belong there — wall-clock timings live in
`incremental-scale-reference-v1.json`, which names the host it was measured
on and is explicitly not a threshold.

## Verification

Before opening a pull request, run:

```console
python -m unittest discover -s tests -v
python -m gat.demo.workflow
```

When OpenUSD or carrier-signature code changes, install `.[openusd]` and run:

```console
python -m unittest tests.test_openusd tests.test_headless -v
python -m gat.demo.openusd_portability openusd-validation-out
```

## Public validation data

Do not add unpinned downloads or large opaque fixtures. A public model entry
must record its source repository, exact commit, license, source path, byte
size, SHA-256, and measured expected result in
`validation/ifc-corpus-v1.json`. Routine CI data should remain small. Large
models belong in the optional validation tier.

Compatibility work must report unsupported entities explicitly. Partial
ingestion or skipped geometry must never silently authorize an acceptance
decision.
